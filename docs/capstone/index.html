Predicting Positive Content Performance Signals for Search Content Prioritization

A client-aware machine-learning analysis that ranks content items for editorial review using observed search, traffic, click-through, and engagement signals.

Author: Muhammad Faisal · Logistic Regression · 30,000 content items

Abstract

This study asks whether a simple machine-learning model can identify content items associated with positive performance signals and help prioritize editorial review. The analysis uses the FlyRank ML Internship dataset containing 30,000 anonymized content items across 32 pseudonymous clients. A client-aware train/test split was used to evaluate a Logistic Regression classifier against a transparent CTR baseline using observed search visibility, traffic, click-through, and engagement features. At the selected decision threshold of 0.10, the model achieved an F1 score of 0.2983 and recall of 0.9009, compared with an F1 score of 0.1703 and recall of 0.1535 for the CTR baseline. The resulting ranked output is intended as directional decision support for editors deciding which content items deserve review, monitoring, or further investigation.

1. Problem Framing

The central question is whether machine learning can help identify content items showing positive performance signals and prioritize them for editorial attention.

Decision supported: Which content items should an editor prioritize for review based on their observed search visibility, traffic, click-through, and engagement signals?

The unit of analysis is an individual content item. The model produces a probability score and a ranked list that can be converted into editorial recommendations.

The human action supported by the output is prioritization: an editor can investigate a high-ranked item before deciding whether to update, monitor, or otherwise review it.

The cost of a wrong call is primarily editorial effort. A false positive can cause an editor to spend time reviewing a page that does not need immediate intervention, while a false negative can cause a potentially useful review opportunity to be missed.

The analysis uses the anonymized content_refresh_anonymized.csv dataset. Each row represents one content item.

Model features

The final model uses nine numerical features:

impressions_90d, clicks_90d, pageviews_90d, sessions_90d, avg_position, ctr, engagement_rate, scroll_rate, and ai_traffic_pct.

Excluded fields

trend_direction and trend_pct were excluded because they are directly related to the performance outcome and could introduce leakage. performance_positive was used only as the target. client_id and content_id were treated as identifiers rather than predictive features.

Client identifiers were used only for the client-aware split and were never used as model features.

No client names, domains, private queries, credentials, or other client-identifying information are included in the public paper.

4. Model / Analysis

The main model is Logistic Regression, selected because it is a simple, interpretable binary classification method.

Target

The target is the binary performance_positive outcome defined from the dataset's performance information.

Validation design

The dataset was split by client rather than randomly splitting individual content items. The training set contains 25 clients and 23,837 rows, while the test set contains 7 different clients and 6,163 rows.

Client overlap: 0. The testing clients were not present in the training set.

Leakage check

The final leakage check passed. No target-derived or identifier fields were included among the model features.

6. Interpretation

The model identified patterns across search visibility, traffic, click-through, and engagement signals that were associated with the positive performance target.

The strongest practical finding is not that any individual feature causes positive performance. Instead, the model provides a combined signal that can be used to rank content items for further investigation.

Key interpretation: The model is more useful as a broad screening mechanism than as a high-precision automatic classifier.

The relatively modest ROC-AUC of 0.5914 and the large number of false positives indicate that the predictions should be treated cautiously. The analysis does not establish causal relationships between the input features and search performance.

Editorial playbook

1. Review search visibility
Investigate search position, visibility, intent alignment, structure, and topical coverage before deciding whether an update is justified.
2. Monitor
Continue observing performance signals and reassess before taking editorial action.
3. Review CTR / metadata
Investigate titles, descriptions, search-intent alignment, and other factors that may affect observed click-through.

The recommendation output assigned 3,973 items to these three action categories. The remaining 2,190 test items were not assigned to one of these categories by the reported recommendation output.

The recommended workflow is: Rank → Review → Act → Monitor → Reassess.
